# План доработок «Окулус Бизнес» — детальный, по стадиям

Статус ведёт агент-контролёр после каждой стадии. Критерий готовности пункта (DoD):
работает на проде, typecheck/тесты зелёные, пункт отражён в UI.

## Стадия 1 — Быстрые победы (Волна 1)

- [ ] 1.1 **Просроченные действия**: в dashboard.nextActions приходит флаг `overdue`
  (nextActionAt < сегодня). На дашборде просроченные — первым красным блоком «Просрочено (N)»,
  в списке — красная плашка. На карточке сделки в канбане просроченное «⏭» — красным.
  DoD: на проде видно задним числом dated-сделку красной.
- [ ] 1.2 **Причина отказа**: Deal.lostReason (строка). При перемещении сделки в этап с isLost
  UI спрашивает причину (select: Дорого/Не тот профиль/Нет бюджета/Выбрали другого/Остыл/Другое + свой текст),
  сохраняется в сделку. В карточке видна. DoD: перенос в «Отказ» требует причину, она сохраняется.
- [ ] 1.3 **Кнопка «Оплачено» у регулярных платежей**: у каждого активного RecurringItem кнопка
  «Отметить оплату» → создаёт Txn (kind, amount, category, occurredOn=сегодня, комментарий
  «Регулярный платеж») и подсвечивает успех. DoD: один клик — операция появилась в месяце.
- [ ] 1.4 **Экспорт месяца в CSV**: на Финансах кнопка «CSV» — скачивает файл
  `oculus-business-<ГГГГ-ММ>.csv` (дата;доход/расход;категория;сумма;комментарий) по текущему
  месяцу. Клиентская генерация. DoD: файл скачивается, открывается в Excel.
- [ ] 1.5 **Фильтр «Мои сделки»**: в Deal DTO добавлен createdById+createdByName; на доске CRM
  переключатель «Все / Мои». DoD: фильтр работает на проде.
- [ ] 1.6 **PWA**: manifest.webmanifest + SVG-иконки, meta theme-color, ссылка в index.html.
  DoD: Chrome предлагает «Установить приложение».
- [ ] 1.7 **Цели месяца + план/факт**: модель MonthGoal {month, mrrGoal, incomeGoal} (upsert
  через /api/finance/goals), на Финансах — блок «Цель месяца»: редактирование, прогресс-бары
  факт/план (MRR-прирост месяца и доход месяца). DoD: цель сохраняется, бары считаются.

## Стадия 2 — Аналитика (Волна 2)

- [ ] 2.1 **История стадий**: модель DealHistory {dealId, fromStage, toStage, movedAt},
  заполняется при moveDeal; Deal.lastStageChangeAt. В карточке сделки — лента «история».
  DoD: перемещение пишет историю; лента видна.
- [ ] 2.2 **Отчёт по воронке**: GET /api/crm/report: конверсия между этапами (%), среднее время
  в этапе (дни, из истории), средний цикл сделки (создана→выиграна), средний чек.
  UI: экран «Отчёт» из доски CRM (сводные плитки + таблица этапов). DoD: цифры считаются из реальных данных.
- [ ] 2.3 **Время в колонке**: бейдж «N дн.» на карточке сделки (из lastStageChangeAt).
  DoD: видно на доске.
- [ ] 2.4 **Движение MRR**: GET /api/finance/mrr-movement?months=12: по месяцам newMRR (сделки,
  вошедшие в isWon-этап в месяце, из истории) и churnedMRR (ушедшие из него) + линейка тотала.
  UI: график-бары на Финансах → «MRR». DoD: график с тремя рядами.
- [ ] 2.5 **Поток за 12 месяцев**: GET /api/finance/history?months=12 (доход/расход по месяцам
  из Txn) → бары на Финансах. DoD: график виден.
- [ ] 2.6 **Дебиторка**: модель ExpectedPayment {title, amount, dueDate, probability(0-100),
  dealId?}; CRUD + кнопка «Получено» (создаёт Txn, удаляет из списка); блок «Ожидаемые
  поступления» на Финансах; в прогнозе учитываются с коэффициентом probability/100.
  DoD: создание/получение работают, прогноз растёт.

- [ ] 3.7 **Автобэкап**: суточный джоб планировщика: дамп бизнес-таблиц (deal/task/txn/recurring/
  expected/settings/goals + users без секретов) в JSON → gzip → B2 (S3 creds уже настроены),
  ключи `backups/oculus-business-<дата>.json.gz`, хранение последних 14.
